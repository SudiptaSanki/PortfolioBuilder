§03 — The failure taxonomy

Four ways agents fail in production

Nearly every bad run I am handed belongs to one of four classes. Each has a guard; none of the guards is a better prompt.

CLASS 01LOOPS

The agent repeats a call that already returned its answer — rephrased just enough to look new. Each repetition re-sends the whole context, so a loop is the most expensive failure per minute and the easiest to mistake for "the model working hard".

The guardRepeated-call detection (same tool, near-identical arguments, no new information), a hard step cap, and a per-run budget cap that halts instead of warning.

CLASS 02TOOL MISUSE

The wrong tool, the right tool with malformed arguments, or a write where a read was meant. Parsers that silently default a missing argument turn this class invisible: the call "succeeds" and the wrong thing happens.

The guardStrict schemas that reject instead of defaulting, least-privilege tool permissions, and dry-run previews for every write.

CLASS 03CONTEXT LOSS

The fact established at step 2 — the customer's actual order number, the constraint the user stated — is buried or summarised away by step 30, and the agent proceeds confidently on a partial world.

The guardState held outside the prompt (a structured run record the agent reads back), plus summarisation checkpoints that are tested, not trusted.

CLASS 04SILENT WRONG ANSWERS

Fluent, well-formatted, wrong. Nothing alarms, no tool errors, the trace looks clean — the cost lands later, in a refund, a churned customer, a wrong record. The most expensive class precisely because it is invisible in the logs everyone watches.

The guardAn evaluation set of graded real tasks run on every change, and sampled human review of live outputs with the grades fed back into that set.

What moves the price

  • Number of tools the agent can call — every tool is a failure surface that must be reviewed, schema-checked and eval-covered.
  • Daily run volume — tracing, sampling and grading scale with traffic, not with headcount.
  • Evaluation-set size — cases have to be written from your real tasks and graded by a human before any automation is trusted.
  • Regulated domains — finance, health and legal work adds documentation, review and sign-off load.
  • Access — black-box engagements (no traces, no logs) take longer and conclude less; the report will say so.
